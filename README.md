# Бот карточек

Карточки из базы знаний в Telegram, как в Quizlet. Выбрал тему, пришёл
вопрос, ответил в голове, нажал «Ответ» и сверился. Без оценок,
интервалов и напоминаний.

Папка исключена из поиска `kb` (`.kb/core.py`, `ИСКЛЮЧИТЬ`).

## Как устроено

```
меню        /start или /go: кнопки тем, на кнопке число карточек.
            «Всё вперемешку» - все темы сразу
тема        theme в начале файла cards/*.toml. несколько файлов могут
            вести на одну кнопку
проход      карточки темы перемешаны, без повторов: «Сети · 3/32».
            «Ответ» открывает ответ в том же сообщении, дальше
            «Дальше» или «Меню». колода кончилась - снова меню.
            новый проход той же темы - новый порядок
кнопки      из старых сообщений проход не сбивают: «Дальше» срабатывает
            только на текущей карточке
```

Проход у каждого пользователя свой, хранится в `meta` (`session:<chat>`).

## Карточки

`cards/<файл>.toml`. Кнопка меню - `theme` в начале файла, до первого `[[card]]`.
Нет `theme` - кнопкой станет имя файла.

```toml
theme = "Мой пайплайн"            # кнопка меню, до 60 байт

[[card]]
id = "gitleaks-history"          # a-z, 0-9, дефис, до 40 знаков, не менять
q = "вопрос про механизм"
a = """ответ строго по файлу базы. `код` станет моноширинным"""
src = "работа/файл.md:101-104"
kind = "С"                        # С своё, М по методичке
```

`keys` и `need` в старых карточках остались от проверки ответов. Бот их
не читает, но хранит: проверку можно вернуть без правки карточек.
Файлы на `_` не карточки (`_aliases.toml` - сокращения той же проверки).
Карточка, убранная из файла, выключается.
После правок в Telegram `/reload`.

## Запуск

Два контейнера: `bot` и `db` (PostgreSQL 16). Токен у @BotFather,
свой ID у @userinfobot.

```shell
cp .env.example .env    # вписать BOT_TOKEN и ALLOWED_USER_IDS
mkdir -p secrets && chmod 700 secrets
openssl rand -hex 24 > secrets/db_password && chmod 644 secrets/db_password
docker compose up -d --build
docker compose logs -f bot
```

`644` у пароля не опечатка: compose монтирует файл как есть, а в
контейнерах свои пользователи (70 у базы, 10001 у бота). От других
пользователей хоста пароль закрыт `700` на папке.

Потом в Telegram боту `/start`.

На сервер:

```shell
rsync -av --exclude .env --exclude secrets/ .repeat-bot/ user@server:/opt/bots/repeat-bot/
ssh user@server 'cd /opt/bots/repeat-bot && docker compose up -d --build'
```

`.env` и `secrets/` на сервере создаются один раз руками и не копируются.
Новые карточки на сервер: тот же `rsync`, затем `/reload`.

## Команды

```
/start, /go      меню тем
/adduser ID      пустить пользователя. только админ
/deluser ID      убрать пользователя. только админ
/users           кто имеет доступ. только админ
/reload          перечитать cards/. только админ
```

Админы - ID из `ALLOWED_USER_IDS` в `.env`, через запятую. Добавленные
через `/adduser` лежат в таблице `users` и переживают перезапуск. Свой ID
пользователь узнаёт у @userinfobot, потом пишет боту `/start`: первым бот
писать не может.

## Безопасность

- Отвечает только админам из `ALLOWED_USER_IDS` и добавленным через
  `/adduser`, остальным молчит. Пустой список админов: бот не стартует.
- Оба контейнера: не root, корень только на чтение, `cap_drop: ALL`,
  `no-new-privileges`, лимит памяти. Карточки подключены только на чтение.
- Портов не открывает, Telegram опрашивается сам (long polling).
- База в сети `internal` без выхода наружу, портов нет. Бот в ней и в
  обычной сети, до Telegram.
- Пароль базы секретом compose из файла, а не переменной окружения:
  переменные видно в `docker inspect`.
- В карточках не держать паролей и адресов: файл лежит на сервере.
