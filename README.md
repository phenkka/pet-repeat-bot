# Бот повторения

Карточки из базы знаний в Telegram. Пришёл вопрос, ответ пишешь
сообщением своими словами. Бот ищет в ответе ключевые пункты карточки
и сам ставит оценку. Интервал у каждой карточки свой.

Папка исключена из поиска `kb` (`.kb/core.py`, `ИСКЛЮЧИТЬ`).

## Как считает

```
меню             /start или /go: кнопки тем. на кнопке «к повторению
                 сегодня + ещё не показано». «Всё вперемешку» - все темы
тема             theme в начале файла cards/*.toml, несколько файлов
                 могут вести на одну кнопку
в теме           сначала возвраты, у которых подошёл срок, самые старые
                 первыми. затем новые: файлы темы по очереди, внутри файла
                 вперемешку, порядок свой на каждый день. нормы нет:
                 вопросы идут, пока не «Хватит» или тема не кончится
засчитано        следующая ступень: 1, 3, 7, 21, 60 дней (INTERVALS)
не засчитано     сброс на первую ступень, завтра снова
«Хватит»         серия встаёт, карточка без ответа не оценивается
напоминание      в REMIND_AT (13:00) меню всегда, в NUDGE_AT (20:00),
                 если остались непройденные возвраты
```

Двойное нажатие и кнопки в старых сообщениях оценку не меняют.

## Как проверяет ответ

Без модели. У карточки 2-3 пункта `keys`, у пункта варианты через `|`.
Пункт засчитан, если в ответе есть все слова хотя бы одного варианта,
в любом порядке. Карточка засчитана, если покрыто 2/3 пунктов или `need`.

Слова сравниваются нестрого (`bot/grader.py`):

```
кириллица в латиницу    «дигест» = digest, «докер» = docker
общее начало от 4 букв  «конф» = конфигурация, «привилег» = привилегий
похожесть от 0.8        опечатки: «привелегии», «гитликс»
слова до 3 букв         только точно
```

После оценки видно, какие пункты найдены, и эталон. Засчитанное можно
понизить кнопкой «Всё равно не знал». Повысить нельзя.
«Не помню» - сразу эталон, не засчитано. Ответ короче 3 слов не принимается.

## Споры

Ответ не засчитан, а ты считаешь его верным - «Оспорить». Оценка не
меняется: засчитать задним числом нельзя. Ответ уходит в таблицу `disputes`.

```
/disputes    открытые споры: ответ и какие пункты не найдены.
             переслать на разбор целиком
/drop 12     разобран, ответ правда неверный
```

Разбор: в карточку дописывается вариант, которым ты это сказал, или
в `cards/_aliases.toml` своё сокращение («прст» = «просто»). Опечатки туда
не нужны, их прощает сравнение. После `/reload` споры, которые теперь
засчитываются, закрываются сами.

## Карточки

`cards/<файл>.toml`. Кнопка меню - `theme` в начале файла, до первого `[[card]]`.
Нет `theme` - кнопкой станет имя файла.

```toml
theme = "Мой пайплайн"            # кнопка меню, до 60 байт

[[card]]
id = "gitleaks-history"          # a-z, 0-9, дефис, до 40 знаков, не менять
q = "вопрос про механизм"
a = """ответ строго по файлу базы. `код` станет моноширинным"""
src = "работа/файл.md:101-104"
kind = "С"                        # С своё, М по методичке
keys = [                          # что обязано быть в ответе
  "полный клон | GIT_DEPTH | shallow",
  "все ветки | all | log-opts",
  "история | старый коммит",
]
need = 2                          # не обязательно. по умолчанию 2/3 пунктов
```

Файлы на `_` не карточки: `_aliases.toml` это сокращения.
Правка текста прогресс не сбрасывает, прогресс привязан к `id`.
Карточка, убранная из файла, выключается, история остаётся.
После правок в Telegram `/reload`.

## Запуск

Два контейнера: `bot` и `db` (PostgreSQL 16). Токен у @BotFather,
свой ID у @userinfobot.

```shell
cp .env.example .env    # вписать BOT_TOKEN и ALLOWED_USER_IDS
mkdir -p secrets && chmod 700 secrets
openssl rand -hex 24 > secrets/db_password && chmod 644 secrets/db_password
docker compose up -d --build
docker compose logs -f bot
```

`644` у пароля не опечатка: compose монтирует файл как есть, а в
контейнерах свои пользователи (70 у базы, 10001 у бота). От других
пользователей хоста пароль закрыт `700` на папке.

Последние ответы прямо из базы:

```shell
docker compose exec db psql -U repeat -c "select day, card_id, ok, answer from log order by id desc limit 20"
```

Потом в Telegram боту `/start`. Без этого он не сможет прислать
напоминание: Telegram не даёт боту писать первым.

На сервер:

```shell
rsync -av --exclude .env --exclude secrets/ .repeat-bot/ user@server:/opt/bots/repeat-bot/
ssh user@server 'cd /opt/bots/repeat-bot && docker compose up -d --build'
```

`.env` и `secrets/` на сервере создаются один раз руками и не копируются.
Новые карточки на сервер: тот же `rsync`, затем `/reload`.

## Команды

```
/start    сколько карточек сегодня
/go       повторять
/stats    сколько всего, по ступеням, что завтра, сколько споров
/disputes открытые споры
/drop N   закрыть спор как неверный
/reload   перечитать cards/ и _aliases.toml
```

## Безопасность

- Отвечает только ID из `ALLOWED_USER_IDS`, остальным молчит. Пустой
  список: бот не стартует.
- Оба контейнера: не root, корень только на чтение, `cap_drop: ALL`,
  `no-new-privileges`, лимит памяти. Карточки подключены только на чтение.
- Портов не открывает, Telegram опрашивается сам (long polling).
- База в сети `internal` без выхода наружу, портов нет. Бот в ней и в
  обычной сети, до Telegram.
- Пароль базы секретом compose из файла, а не переменной окружения:
  переменные видно в `docker inspect`.
- В карточках не держать паролей и адресов: файл лежит на сервере.
